## Shared agent workflow (Cursor / Codex)

このブロックは `kdob1042/mac-enabler` から生成された共通運用部分です。直接編集せず、mac-enablerを更新して同期します。

- このリポジトリの `AGENTS.md`、設計書、スクリプト、CIをプロジェクトの正本として扱い、兄弟リポジトリのルールを推測で読み込まない。
- リポジトリ固有のブランチ／PRルールを守り、保護ブランチへ直接pushしない。
- 変更範囲を満たす最小の検証を実行し、未実行の検証と理由をIssue／PRへ残す。
- 設計・スキーマ・デプロイ・公開契約の変更では、対象リポジトリの正本文書と受入条件を先に確認する。
- 同一Issueの実装担当は1つとし、既存の開始／担当取得手順と最新PRを確認する。並列作業は独立Issue・別作業ツリーに分け、引き継ぎ時は前担当の停止と担当移管を確認する。
- 1つのセッションへ無関係なIssueを継ぎ足さない。実装・ツール履歴が大きくなった状態で次の独立タスクへ進む場合は、Issue／PRへ現在地を保存して新しいセッションへ切り替える。
- サブエージェントは独立して完結できる限定タスクにだけ使い、同じ変更を複数agentへ重複調査させない。レビューは指摘を1回でまとめ、修正をまとめて行い、最後に再確認する。細かな `review → fix → review` の往復を常態化させない。
- 長時間のtest／build／deployを別agentに監視させたり、短い間隔でモデルターンを消費してpollし続けたりしない。可能なら1回のコマンド実行を完了まで待ち、終了結果・失敗ログ・exit codeをまとめて確認する。
- 検証は変更範囲に近い小さい確認から始め、全体test／buildは必要な境界でまとめて実行する。同じ重い検証を小さな編集のたびに理由なく繰り返さない。
- コンパクションまたは引き継ぎの前に、目標、制約、正本、担当、ブランチ／PR、head SHA、検証済みSHA、未push変更、検証結果、残件、未解決事項、次の一手を永続的なIssue／PRへ保存する。
- コンパクションまたは引き継ぎの後は、適用範囲内の `AGENTS.md` と最新の引き継ぎ記録・head SHAを確認し、記録された次の一手から再開する。
- モデル設定、共通Skill、認証、Secrets、会話履歴はホスト間で自動共有されたと仮定しない。資格情報をrepoや引き継ぎ記録に含めない。
- プロジェクト固有の事実、コマンド、受入条件、ブランチ規則はこの共通ブロックより優先する。

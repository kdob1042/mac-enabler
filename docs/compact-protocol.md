# コンパクション・引き継ぎプロトコル

## 目的

会話のコンテキストが圧縮されても、作業を最初からやり直さず、GitHub上の状態から再開できるようにする。

## できることとできないこと

- ChatGPT／Codexのコンパクションや自動要約はホスト側の機能であり、リポジトリから強制できない。
- `mac-enabler` が保証するのは、コンパクション前に再開に必要な状態を保存する手順である。
- モデルの切り替えは、現在のUIが自動ルーティングを提供しない場合は強制できない。ルーターは必要な能力と、使う場合のプロファイルを整理する。

## コンパクション前

コンパクションまたは引き継ぎが必要な作業では、次の情報をIssueコメント・PR本文／コメントなど対象リポジトリで定めた永続的な場所へ保存する。

```markdown
## Handoff packet

- Goal:
- Scope and constraints:
- Source of truth:
- Branch / PR:
- Changed files:
- Tests and results:
- Remaining work:
- Next action:

<!-- 必要な場合だけ追加 -->
- Route and model profile:
- Unresolved decisions:
```

全作業で機械的に同じパケットを作る必要はありません。短い作業でも、次のセッションや別エージェントが再開する可能性がある場合は、少なくとも「現在地」と「次の一手」を残します。失敗した検証を成功扱いにしません。

## コンパクション後

1. 対象リポジトリのルートと適用範囲内の `AGENTS.md` を読む。
2. 最新のIssue／PRと引き継ぎパケットを読む。
3. ブランチ、PR、変更ファイル、未コミット状態を確認する。
4. パケットの `Next action` から再開する。
5. 既に行った探索を理由なく繰り返さない。

## 保存先の優先順位

1. 対象リポジトリのIssue／PR
2. 対象リポジトリが定める作業状態ファイル
3. 最後の手段として会話内の引き継ぎ文

会話だけを正本にしない。
